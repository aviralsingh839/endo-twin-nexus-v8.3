# Data Architecture - CHRONO-TWIN NEXUS V8.3

## Organization

```
data/
├── raw/              # Raw sensor exports, packet logs (REAL, gitignored)
├── processed/        # Processed feature CSVs (REAL or SYNTHETIC)
├── clinical/         # Clinical variables entered manually (USER-ENTERED)
├── physiological/    # Physiological features from wearables (REAL or SYNTHETIC)
├── longitudinal/     # Longitudinal timelines per subject (REAL or SYNTHETIC)
├── ultrasound/       # Ultrasound images and structured features (REAL or CLINICAL)
├── synthetic/        # Synthetic longitudinal data and scenarios (SYNTHETIC)
├── public/           # Public datasets (PUBLIC DATASET)
└── baselines/        # Personal baselines (REAL, gitignored)
```

## Labeling - CRITICAL

Every dataset must be clearly labelled:

- **REAL**: Directly measured from hardware
- **SYNTHETIC**: Generated by synthetic.py with realistic variation
- **SIMULATED**: Hardware simulator or demo stream
- **PUBLIC DATASET**: From public sources (Kaggle PCOS, PhysioNet)
- **USER-ENTERED**: Manually entered by user (BMI, BP, glucose, cycle)

Never mix these silently.

## Synthetic Data - V8.3

Located in `synthetic/`:

- Individual baselines per subject
- Age, BMI, activity patterns, resting HR, HRV, sleep timing/duration, temperature trends, GSR patterns, menstrual-cycle info, clinical variables
- Gradual physiological changes, temporary disturbances, sensor noise, missing data, motion artifacts, recovery periods
- Timeline: DAY 1 → DAY 30 → DAY 60 → DAY 90 (not independent random)

### Longitudinal Scenarios (6 required)

1. **Stable baseline** - Physiology within normal variation → LOW CHANGE SIGNAL
2. **Gradual deviation** - Parameter slowly moves away → EARLY CHANGE SIGNAL
3. **Persistent deviation** - Multiple related signals abnormal → PERSISTENT MULTIMODAL SIGNAL
4. **Temporary disturbance** - Brief change then return → TEMPORARY EVENT
5. **Sensor failure** - One sensor stops → LOW SENSOR CONFIDENCE (must not be interpreted as physiological abnormality)
6. **Recovery** - Abnormal returns toward baseline → RECOVERY TREND

All synthetic data is clearly labelled `SYNTHETIC` and never presented as real clinical data.

## Runtime Files (gitignored)

- `chrono_pcos.db` / `chrono_twin_nexus.db` - SQLite history
- `raw/` - raw CSV exports
- `baselines/` - personal baseline JSONs
- `training_audit.jsonl` - training audit log
- `ai_config.json` - optional assistant config

## Data Honesty

- Never create fake clinical results and present as real
- Never modify public datasets to improve metrics
- Never fabricate patient records
- Never label synthetic as clinical
- Never claim diagnosis unless clinically validated

Use language:
- "research risk signal"
- "physiological deviation"
- "screening-oriented estimate"
- "requires clinical evaluation"
