## Labeling - Critical

Every dataset clearly labelled:

- **REAL**: Directly measured from hardware (Nano pod, Mega hub)
- **SYNTHETIC**: Generated by `src/utils/synthetic.py` with realistic variation, circadian modulation, noise, missing data
- **SIMULATED**: Hardware simulator or demo stream
- **PUBLIC DATASET**: From public sources (Kaggle PCOS, PhysioNet)
- **USER-ENTERED**: Manually entered by user (BMI, BP, glucose, cycle)

Never mix silently. Every JSON includes `"label": "SYNTHETIC"` etc.

## Synthetic Data - V8.3 Improvements

Old synthetic was random numbers. New synthetic is realistic longitudinal:

**Per Subject:**
- Individual baselines: age, BMI, resting HR, HRV, skin temp, activity, sleep duration/timing, cycle length, cycle irregular, BP, glucose
- Variability: hr_variability, hrv_variability, temp_variability, base_quality
- Timeline: DAY 1 → DAY 30 → DAY 60 → DAY 90, not independent random

**Per Sample (24 samples/day example):**
- Circadian modulation: HR higher during day, temp rhythm, activity day/night pattern
- Sleep: duration, regularity, probability based on time and motion
- Stress: higher midday, influenced by scenario
- Sensor realism: noise, missing data (2% random), motion artifacts (3%), flatline, packet corruption
- Quality: per-feature quality with noise

**Scenarios (6 required):**
1. Stable: small random variation around baseline → LOW CHANGE SIGNAL
2. Gradual: hr_slope_per_day 0.12-0.15 bpm/day, hrv_slope -0.25, temp +0.01/day, activity -0.2/day → EARLY CHANGE SIGNAL
3. Persistent: after day 20, HR +8 plus 0.1/day, HRV -12, temp +0.4, activity -10, sleep -0.8h → PERSISTENT MULTIMODAL SIGNAL
4. Temporary: days 30-33 brief disturbance HR +15, HRV -15, temp +0.6, quality -0.1 → TEMPORARY EVENT
5. Sensor failure: after day 25, HR missing 70% or flatline, quality 0.2 → LOW SENSOR CONFIDENCE (must not be interpreted as physiological)
6. Recovery: days 0-10 normal, 10-35 abnormal then gradually returns (initial offset * (1-progress)) → RECOVERY TREND

**Generation:**
```python
from src.utils.synthetic import generate_scenario_dataset, generate_synthetic_cohort
generate_scenario_dataset(Path("data/synthetic/scenarios"), seed=42)  # 6 scenarios, 60 days, 24/day
generate_synthetic_cohort(n_subjects=10, days=30, samples_per_day=12, output_dir=Path("data/synthetic/cohort"))
```

**Cohort:** 10 subjects diverse baselines (age 16-45, BMI 18.5-32, RHR 60-80, HRV 30-60, temp 31.5-33.5, activity 20-50, sleep 6.5-8.5, cycle 21-35 days, 20% irregular), mix scenarios stable 40%, gradual 20%, persistent 15%, temporary 15%, recovery 10%

## Clinical Data

- Location: `data/clinical/` or `history_store` SQLite
- Label: USER-ENTERED
- Fields: age, BMI, height, weight, waist, systolic/diastolic BP, cycle day, usual length, days since last period, years post menarche, cycle irregular (bool), glucose mg/dL, glucose context, time since meal, sex, smoking, family history
- Never treated as MEASURED

## Physiological Data

- Location: `data/physiological/` or SQLite
- Label: REAL or SYNTHETIC
- From FeatureVector: hr_bpm, resting_hr, rmssd, skin_temp, activity, sleep_duration, etc.
- Quality per feature

## Longitudinal Data

- Location: `data/longitudinal/` or SQLite
- Label: REAL or SYNTHETIC
- Timeline per subject, subject-level split for validation (no leakage)

## Ultrasound Data

- Location: `data/ultrasound/`
- Label: REAL or CLINICAL
- Provenance preserved: source image → preprocessing → detected features → quality → uncertainty
- If feature cannot be reliably extracted: UNKNOWN, never invented
- Structured features: cyst_size_mm, volume_cc, morphology
- Source: CLINICALLY-ENTERED or IMAGE-DERIVED
- Quality gated

## Baselines

- Location: `data/baselines/`, gitignored
- Label: REAL (personal)
- Files: personal_baseline_v8_3.json, calibration_history_v8_3.json
- Contains: captured_at, duration_s, samples, days_covered, quality, confidence, stats per metric

## Runtime Files (gitignored)

- `chrono_pcos.db` / `chrono_twin_nexus.db` - SQLite history (sessions, features, logs, care plan, reports)
- `raw/` - raw CSV exports

## Data Honesty

- Never create fake clinical results and present as real
- Never modify public datasets to make metrics look better
- Never fabricate patient records
- Never label synthetic data as clinical data
- Never claim diagnosis unless clinically validated
- Use: "research risk signal", "physiological deviation", "screening-oriented estimate", "requires clinical evaluation"
- Check: `tests/test_validation.py` verifies labels

## Subject-Level Validation

- Splitting must happen at SUBJECT level when appropriate
- Same person must not appear in both training and validation folds when that would leak
- Synthetic cohort preserves subject_id in shared_features
- Test `test_subject_level_validation` verifies no overlap

## Reproducibility

- Seeds fixed for synthetic generation
- Same seed → same timeline
- Test `test_reproducibility` verifies
